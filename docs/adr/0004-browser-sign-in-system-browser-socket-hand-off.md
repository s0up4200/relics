# Browser sign-in uses the system browser and a socket hand-off

The app does Browser sign-in in a normal tab of the system browser, and catches the return through the `org.siloserver.silo:` link scheme of the official apps. A second process that the browser starts gives the link to the running app over a Unix socket in `$XDG_RUNTIME_DIR`. We did not use a web view inside the app. Identity providers such as Google block web views, RFC 8252 says that native apps must not use them, and password managers and passkeys do not work in them. A web view removes the need for the scheme handler and the socket, but it adds WebKitGTK and fails at those providers. The Server fixes the return link to this scheme and offers no loopback redirect, so we share the scheme with the official apps.
